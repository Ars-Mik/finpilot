# FinPilot — бюджеты и месячные лимиты (этап 08)

## Функциональность

- Страница `/budgets`: месячные лимиты по расходным категориям, сумма расходов за выбранный месяц, оставшийся лимит и превышение.
- `GET /api/budgets?month=YYYY-MM` возвращает сводку, включая расходы без установленного лимита.
- `POST /api/budgets` создаёт лимит на месяц/категорию; дубль возвращает 409.
- `PATCH /api/budgets/:id` изменяет только `limitCents`; `DELETE /api/budgets/:id` удаляет лимит без удаления операций.
- Применяется миграция `003_monthly_budgets.sql`: новая таблица и частичный индекс расходов. Старые операции, счета и переводы не изменяются.
- Лимиты распространяются на все счета. Переводы между своими счетами **не учитываются** в расходах. Доходы не учитываются.
- Расчёт выполняется из PostgreSQL при каждом запросе. Изменение/удаление исторической операции влияет на соответствующий месячный бюджет после обновления страницы.
- Денежные значения хранятся в целых копейках; на сервере проверяются категории, суммы и даты.

## До установки

**Не изменяй существующие миграции `001_...` и `002_...`.** Их контрольные суммы проверяются мигратором.

Если в базе важные данные, перед применением миграции сделай и проверь дамп PostgreSQL:

```powershell
cd C:\Users\ars04\Desktop\finpilot
docker compose up -d postgres
New-Item -ItemType Directory -Force .\backups | Out-Null
cmd /c "docker compose exec -T postgres pg_dump -U finpilot -d finpilot -Fc > backups\finpilot_before_budgets.dump"
Get-Item .\backups\finpilot_before_budgets.dump | Select-Object Name, Length
cmd /c "docker compose exec -T postgres pg_restore -l < backups\finpilot_before_budgets.dump > NUL"
```

Проверь код завершения команды `pg_restore -l`: `$LASTEXITCODE` должен быть `0`. Не добавляй дампы и `.env` в Git.

## Проверка в браузере

1. Открой `/budgets` и выбери месяц с уже сохранёнными расходами.
2. Создай лимит «Продукты» 5000 ₽. Траты по категории должны учесть операции **всех** счетов за выбранный месяц.
3. Создай расход «Продукты» на 6000 ₽, обнови страницу. Должен появиться красный индикатор и превышение 1000 ₽.
4. Измени лимит на 7000 ₽. Превышение исчезнет, остаток станет 1000 ₽.
5. Убедись, что невозможно добавить второй лимит «Продукты» на тот же месяц.
6. Создай лимит в соседнем месяце: значения не должны смешиваться.
7. Удали лимит, обнови страницу: расходы не исчезнут, но войдут в «Без установленного лимита».
8. Добавь перевод между собственными счетами: расходы по бюджетам не должны измениться.
9. Отключи API и обнови страницу: должен появиться текст ошибки с возможностью повторить запрос.

## Ограничения

- Лимиты указываются вручную для выбранного месяца; автоматический перенос в следующий месяц будет отдельным этапом.
- Пока нет авторизации и разделения данных пользователей. Приложение остаётся локальным, API нельзя публиковать в открытый интернет.
- Тесты API используют fake-репозиторий. Миграцию и PostgreSQL-запросы обязательно проверить локально: тесты не заменяют настоящие SQL integration tests.
- Очень большие суммы могут превысить диапазон безопасных целых JavaScript. Сервер в этом случае не возвращает неточные суммы, а сообщает об ошибке.
