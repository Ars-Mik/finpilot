# FinPilot — React ↔ REST API (этап 03)

## Запуск локально

1. `docker compose up -d postgres` из корня репозитория.
2. `cd server`, `npm run db:migrate`, `npm run dev`.
3. Открой второй терминал: `cd client`, `npm run dev`.
4. Зайди на `http://localhost:5173/`. Сначала база будет пустой; нажми «Загрузить демоданные».

Фронтенд обращается к API по умолчанию на `http://127.0.0.1:3001`. Чтобы изменить адрес, создай `client/.env.local` и укажи `VITE_API_BASE_URL=http://127.0.0.1:3001`. Не храни пароли и токены в переменных `VITE_*`: они доступны в браузере.

## Что изменилось

- Загрузка из `GET /api/transactions` с обходом страниц API по 100 записей (временно для MVP; до масштабирования перейдём на серверную пагинацию и отдельные агрегирующие запросы).
- Создание через `POST /api/transactions`, удаление через `DELETE /api/transactions/:id`.
- Загрузка, ошибки сети и API, блокировка повторных отправок формы.
- Загрузка демонстрационных операций в локальную базу через существующий CRUD API.

## Важные ограничения

- Старый ключ `finpilot.transactions.v1` остаётся в `localStorage` браузера, но **автоматически не импортируется** в базу: нельзя незаметно создавать дубликаты. Не удаляй `localStorage` до отдельного этапа импорта старых операций.
- Кнопка «Загрузить демоданные» удаляет все текущие записи API и создаёт новые. Операция **не транзакционная**; в случае сбоя данные перечитываются с сервера. Использовать только локально с демонстрационными данными.
- Пока нет авторизации и изоляции пользователей, **не публикуй API в интернет** и не вводи реальные финансовые данные.
- В `server` ранее `npm audit` показывал уязвимости. Проверяй актуальное состояние через `npm audit` и `npm audit --omit=dev`; не запускай `npm audit fix --force` без анализа.

## Проверка

```powershell
cd client
npm run build
npm run lint
npm run dev
```

В браузере: пустая база → демоданные → создать доход/расход → обновить страницу → удалить запись → обновить страницу. Если backend выключить, в интерфейсе должна появиться ошибка подключения.
