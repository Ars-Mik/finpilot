# FinPilot — регулярные операции (этап 09)

Версия изменений: после коммита `790d431` (`add monthly budgets`). Перед установкой не должно быть несохранённых изменений, которые перезапишет архив.

## Что добавлено

- Страница `/recurring`: недельные и месячные правила для доходов и расходов.
- Привязка каждого правила к счёту и категории.
- Просмотр ближайших трёх запланированных дат, пауза и возобновление.
- Явная запись наступивших операций в таблицу `transactions`.
- Суммы на счетах, операции, бюджеты и главная сводка автоматически учитывают созданные записи.
- База защищает от повторного начисления правила за ту же запланированную дату уникальным индексом.

## Границы поведения

- **Автоматического фонового списания нет**. Нажатие «Записать наступившие операции» записывает платежи по активным правилам с начала последних 12 месяцев до **текущей UTC-даты включительно**.
- При создании правила баланс не меняется. Для добавления новых операций требуется отдельное подтверждение.
- Начало на 29, 30 или 31 число месяца корректируется до последнего календарного дня короткого месяца; это не меняет опорный день в следующих месяцах.
- При отключении правило не удаляется, история транзакций остаётся неизменной.
- Повторный запуск не создаёт дубли по `(recurring_rule_id, recurring_occurrence_date)`.
- Изменение или удаление уже созданной операции в обычном списке не редактирует расписание. **Удалённую автоматически сформированную операцию повторный запуск создаст заново.** Для прекращения будущих начислений выключи правило. В следующих версиях добавим исключения/пропуски конкретных начислений.
- Пока в приложении нет авторизации; **не публикуй API в интернет и не используй реальные финансовые данные**.

## Новые API

- `GET /api/recurring?on=2026-10-20` — список с предстоящими датами.
- `POST /api/recurring` — новое правило.
- `PATCH /api/recurring/:id` с `{ "enabled": false }` — пауза или возобновление.
- `POST /api/recurring/apply` с `{}` — запись наступивших начислений; ответ `{ "data": { "created": N, "alreadyRecorded": N } }`.

Пример создания:

```json
{
  "title": "Интернет",
  "type": "expense",
  "category": "Подписки",
  "amountCents": 89000,
  "accountId": "UUID_СУЩЕСТВУЮЩЕГО_СЧЁТА",
  "frequency": "monthly",
  "startDate": "2026-10-20",
  "endDate": null
}
```

## Реализация

- SQL: `004_recurring_rules.sql` добавляет только новые таблицы/поля, данные существующих операций не изменяются.
- Расчёт дат: `server/src/modules/recurring/schedule.ts` — чистые функции UTC.
- Запись начислений: транзакция PostgreSQL (`BEGIN`/`COMMIT`), блокировка расписаний `FOR UPDATE`, параметризованные INSERT, уникальный индекс и `ON CONFLICT DO NOTHING`.
- Учитываем только записи реальных транзакций; правило само по себе не является расходом/доходом в балансах или бюджетах.

## Известные ограничения тестирования

Локальные тесты API используют fake-репозиторий и отдельно проверяют вычисление дат. Они не заменяют тестирование миграции, SQL, уникального индекса и повторного начисления на реальном PostgreSQL. Выполни интеграционную проверку из `QA_STAGE09.md`.
