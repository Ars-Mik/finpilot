# FinPilot — этап 13: UI-аудит и автоматические проверки

Исходная точка: `main`, коммит `e2dfdec` (`improve ui design`). Обновление не меняет REST API, SQL, миграции и финансовые проводки.

## Что исправлено

1. В обзоре заголовок баланса уточнён: «Общий остаток на счетах». Значение включает начальные остатки и финансовые операции; внутренние переводы на общую сумму не влияют.
2. Бюджеты: прежняя подпись «Расходы в пределах категорий с лимитами» была неверной при превышении бюджета. Теперь написано «Расходы в категориях с лимитами».
3. Бюджеты: суммарное превышение считается **по каждой категории отдельно**, а не через разницу суммы лимитов и суммы расходов. Недоиспользованный лимит одной категории больше не маскирует перерасход другой.
4. Аналитика: когда предыдущий период имеет нулевые показатели, сравнение не создаёт иллюзию корректного темпа роста; вместо этого показывается «Нет данных за предыдущий период».
5. Добавлен Playwright: базовая навигация по семи разделам, переключение тем, доступность диалога по клавиатуре, мобильная навигация и регрессии сводок.
6. Добавлен GitHub Actions workflow для проверок frontend и backend, включая UI smoke-тесты без доступа к реальным данным и PostgreSQL.

## Установка

Из корневой папки проекта распакуй архив с заменой существующих файлов. Затем:

```powershell
cd C:\Users\ars04\Desktop\finpilot\client
npm install --save-dev @playwright/test
npx playwright install chromium
npm run build
npm run lint
npx playwright test
```

Playwright сам поднимет отдельный Vite на порту `5179`, чтобы не мешать обычному `5173`. Backend и PostgreSQL ему **не нужны**: тесты перехватывают API-запросы и используют изолированные фиктивные ответы.

Убедись, что порт `5179` свободен. Если он занят, останови процесс или измени номер порта одновременно в `client/playwright.config.ts`.

Проверка backend не требуется для исправлений текста, но CI автоматически выполняет `npm run build`, `npm test` и `npm audit --omit=dev`.

## Проверки вручную

- Светлая и тёмная темы на каждой странице.
- Ширина 320, 390, 768, 1024 и 1440 px; горизонтальная прокрутка отсутствует, кроме таблиц со специальным контейнером.
- В бюджетах 2 категории: один перерасход и другой недорасход; общий перерасход не должен пропадать.
- Escape закрывает форму новой операции. Фокус возвращается на кнопку открытия.
- Сравнение аналитики с периодом, в котором не было операций.
- В мобильном меню доступны все семь разделов.

## Известное ограничение и следующий этап

Публичный backend сейчас без авторизации. Текущая кнопка «Загрузить демоданные» изменяет общую локальную БД, а не индивидуальные данные пользователя. **Нельзя выставлять этот API публично.** Следующий большой этап — безопасное разделение тестовых/гостевых данных и рабочих данных, затем публичный деморежим с возможностью вернуть исходное состояние. Не публикуй сайт с доступным для всех API CRUD до реализации этой защиты.
